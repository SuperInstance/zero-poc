# Playtest — zero-poc from the outside (2026-10-27, after v0.7)

Method, three angles, no author-machine state trusted:

1. **Cold clone.** Fresh public clone of this repo (HEAD `7941ba3`)
   on a separate machine; only documented commands run.
2. **Persona probes.** Six messages from six different asker
   stances, fired through the *real* telegram pipeline via the
   v0.6.1 dry-run route (`via: cli-test`, recorded, not delivered).
   Each answer graded against the conversation record, not vibes.
3. **Fresh-instance read.** A model that has never seen the
   project (MiniMax-Text-01) given only `README.md` + `TOOLS.md`.

## Cold clone

- Zero author-machine paths anywhere in the tree (the failure
  class that sank the xero-lab grid in its 2026-10-13 playtest —
  absent here).
- `python3 -m pytest tests/` — **63/63 pass** from the clone.
- The README quickstart is honest about its one hard gate: a fork
  does nothing until it is registered with the vault (VAULT.md).
  That is a documented gate, not a hidden defect.

## Fresh-instance read

Comprehension: accurate (git-native agent, vault-held secrets,
repo as memory). First move an outsider would try: fork, follow
VAULT.md registration, watch the activity — the documented path,
taken as written. Skeptic's list, in its words: vault security
specifics, which LLM and at what cost, how the agent chooses
among tools, error handling and recovery, whether GitHub's cron
throttling makes it too slow, and how the sibling repos fit.
Most of those answers exist deeper in `docs/` — they are simply
invisible from the front door (see D2).

## Deficits found

- **D1 — the voice overpromises delivery.** Probe 5's reply: "I'll
  let you know what I find out!" There is no proactive channel:
  today a result can only surface on the human's next message.
  (Note: the board claim itself is true of the production path —
  every telegram message routes to TASKS.md. The dry-run harness
  deliberately skips that routing, and the voice cannot know; the
  overpromise is the real defect, not the board claim.) Cure is
  the already-queued board-reports work, or a brief wording
  change: results arrive on next contact.
- **D2 — the front door hides the failure story.** The repo's
  recovery behaviour is genuinely documented (workflow headers,
  `docs/maintenance-notes.md` — including a live silence bug and
  its fix), but a cold reader meets none of it and reasonably
  asks "what happens when it breaks?" One short README section
  pointing at the maintenance notes would answer the outsider's
  sharpest question. Recommendation only; not applied here.

## Verdict

From the outside, v0.7 is what its docs claim: a stranger can
clone it, run its tests, and understand it; six different
askers got six truthful answers, including the two the pre-v0.7
agent measurably failed (deep reference) or would have been
tempted to fake (absent fact). Remaining gap is delivery, not
memory: the loop works in silence until spoken to (D1).
